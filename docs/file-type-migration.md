# 文件类型云端迁移

文件类型现在由工作区云端资源 API 管理。旧版本曾将完整快照保存到
`workspaceFileTypes:<workspaceId>:v1` 本地 key。

首次进入文件类型管理页时，管理员会自动执行一次迁移：

1. 按 `template_key` 合并系统默认类型的描述、启用状态和排序；
2. 导入本地自定义类型，服务端生成新的 workspace-scoped ID；
3. 保留云端已有但本地没有的自定义类型；
4. 强制“未分类”启用并位于当前范围末尾；
5. 云端事务成功后删除旧本地快照。

迁移接口为 `POST /v1/workspaces/{workspaceId}/file-types/migrate`。迁移服务是
唯一允许读取旧本地 key 的代码，页面本身只调用 `resource-api`。请求失败时本地
快照会保留，并在页面显示错误 toast；重新进入页面可以再次尝试。

## 部署与故障排查

文件类型路由随 API 镜像发布，不会通过前端热更新自动进入已经运行的容器。
数据库需要先完成到迁移版本 15（包含 `file_type_templates` 和 `file_types`），
然后使用包含 `file_types.go` 的源码重新构建并重启 API 容器。不要在本次修复中
运行尚未发布的后续资源类型迁移。

如果页面提示“接口尚未部署”，先检查：

1. `GET /readyz` 是否成功；
2. 使用有效工作区会话请求 `GET /v1/workspaces/{id}/file-types?scope=workspace`，
   正常应返回 `200` 和资源列表，而不是 `404`；
3. 使用管理员会话请求 `POST /v1/workspaces/{id}/file-types/restore`，
   正常应返回该范围恢复后的完整列表。

若 `readyz` 正常但上述路由仍为 `404`，说明容器仍在运行旧镜像，需要重新构建
API 镜像并执行 API 服务的强制重建；前端刷新本身不会修复该问题。

文件类型目前尚未被 `files` 表引用，因此删除自定义类型只执行软删除。未来增加
文件归类关联后，应在删除前增加转移到“未分类”的策略。
